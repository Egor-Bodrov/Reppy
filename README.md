# Лабораторная работа 4. Циклы, счётчики и накопители

## Что делают программы

### 1. `range_numbers.py`

- Вводятся целые `a` и `b`.
- `a < b` → цикл `range(a, b + 1)` печатает по возрастанию.
- `a > b` → `range(a, b - 1, -1)` печатает по убыванию.
- `a == b` → печатается одно число.

`range(a, b)` сам по себе **не** подходит для задания: `b` в диапазон не входит, а при `a > b` такой `range` вообще пуст — нужен `b + 1` или отрицательный шаг.

### 2. `statistics.py`

- Вводится `n >= 1`, затем ровно `n` целых чисел. Список не используется.
- `total` — накопитель суммы.
- `positives` — счётчик положительных.
- `maximum` инициализируется первым введённым значением (через `None`), чтобы корректно работать со всеми отрицательными числами.

### 3. `positive_input.py`

- Запрашивает число, пока не будет введено положительное.
- `rejected` считает отклонённые попытки.
- Цикл **гарантированно завершится**: при вводе положительного числа условие `number <= 0` станет ложным.

### 4. `variant.py` (вариант 8)

- Вводится `n >= 0`, затем `n` целых чисел.
- Одним циклом считаются количество и сумма чисел, у которых `abs(value) > 5`.
- Если подходящих чисел нет, оба результата равны `0`.

## Таблица значений для суммирования чисел 1–4

```python
total = 0
for number in range(1, 5):
    total += number
```

| Итерация | `number` | `total` до | `total` после |
| --- | --- | --- | --- |
| 1 | 1 | 0 | 1 |
| 2 | 2 | 1 | 3 |
| 3 | 3 | 3 | 6 |
| 4 | 4 | 6 | 10 |

После цикла `total == 10`.

## Почему циклы завершаются

- `for` по `range(...)` конечен: число итераций равно длине диапазона.
- `while` в задании 3 зависит от ввода, но условие `number <= 0` рано или поздно станет ложным, потому что программа требует именно положительное число.
- В `variant.py` цикл `for i in range(n)` выполняется ровно `n` раз при `n >= 0`.

# Лабораторная работа 5. Обработка строк

Индивидуальный вариант — **вариант 8** (слово содержит ровно одну букву «а»).

| `variant.py` | Индивидуальный вариант 8 |

Запуск: `python имя_файла.py`.

## Что делают программы

### 1. `normalize.py`

- Вводится строка; `text.split()` без аргумента режет её по любым пробельным символам и отбрасывает пустые части.
- `" ".join(...)` собирает обратно через один пробел — так убираются пробелы по краям и лишние внутри.
- Регистр сохраняется.
- Выводятся: исходная длина, новая длина, нормализованный текст, число слов.
- Слово здесь — непустая часть из `split()`; знаки препинания остаются частью слова.

### 2. `palindrome.py`

- По правилам задания игнорируются **регистр** и **обычные пробелы** `" "`. Остальные символы (включая пунктуацию) сравниваются как есть.
- `text.lower()` — приведение к нижнему регистру (исходная строка не меняется, т.к. `str` неизменяема).
- `.replace(" ", "")` — удаление только обычных пробелов.
- Проверка через срез `cleaned == cleaned[::-1]`.
- Если после очистки строка пуста → `Нет текста`, иначе `Палиндром` / `Не палиндром`.

### 3. `replace.py`

- Сначала `text.count(":")` — считаем вхождения в исходном тексте.
- Затем `text.replace(":", "-")` — получаем новую строку.
- Важно делать замену **после** подсчёта: если сначала заменить, двоеточий уже не будет.
- Выводятся количество замен и новая строка.

### 4. `variant.py` (вариант 8)

- Вводится строка; `text.split()` даёт слова.
- Для каждого слова `word.strip(".,!?;:")` убирает пунктуацию по краям, `.lower()` — нижний регистр.
- Пустые после очистки слова пропускаются.
- Условие отбора: `cleaned.count("а") == 1`.
- Подходящие слова печатаются по одному на строке; в конце — общее количество.
- Если подходящих слов нет — `Нет совпадений`, количество `0`.

## Ключевые идеи

- **Строки неизменяемы.** `text.lower()`, `text.replace(...)`, `text.strip(...)` возвращают **новую** строку; исходная не меняется. Результат нужно присвоить или использовать сразу.
- **Слово ≠ подстрока.** `"армия".count("а")` считает вхождения буквы, `"ар" in "армия"` проверяет наличие подстроки; `split()` выделяет именно слова, разделённые пробельными символами.
- **Правила обработки пунктуации задаются до кода.** В задании 2 пунктуация сравнивается как есть, в варианте — удаляется с краёв. Если смешать правила, ответы будут другими.

# Лабораторная работа 6. Списки и обработка наборов данных

Индивидуальный вариант — **вариант 8** (числа от 10 до 20 включительно).

## Файлы

| Файл | Назначение |
| --- | --- |
| `statistics.py` | Задание 1. Количество, сумма, min, max, среднее |
| `transform.py` | Задание 2. Замена отрицательных на модули |
| `positions.py` | Задание 3. Индексы всех максимумов |
| `variant.py` | Индивидуальный вариант 8 |

Запуск: `python имя_файла.py`.

## Что делают программы

### 1. `statistics.py`

- Вводятся целые числа одной строкой; `split()` + `int()` + `append()` собирают список.
- Если ввод пустой — печатается `Нет данных`, иначе — количество, сумма, минимум, максимум, среднее с двумя знаками (`:.2f`).
- `min()`/`max()` вызываются только для непустого списка, деления на ноль нет.

### 2. `transform.py`

- Формируется **новый** список `absolute`: отрицательные заменяются на `-number` (модуль), остальные копируются как есть.
- Исходный `numbers` не изменяется — это видно по выводу.
- Пустой ввод допустим: выводятся два пустых списка.

### 3. `positions.py`

- Если список пуст — `Нет данных`.
- Иначе определяется `maximum = max(numbers)`, затем через `enumerate()` собираются все индексы, где значение равно максимуму. Порядок возрастает автоматически, т.к. обход идёт слева направо.

### 4. `variant.py` (вариант 8)

- Отбираются числа, для которых `10 <= number <= 20`.
- Выводятся: выборка в исходном порядке, количество, сумма, **новая** отсортированная копия (`sorted(...)`).
- Повторы сохраняются.
- Если подходящих нет — `[]`, `0`, `0`, `[]`.

## Ключевые идеи

- **`append()` vs `items[i] = value`.** `append` добавляет новый элемент в конец (длина растёт), присваивание по индексу заменяет существующий (длина не меняется). Присваивание несуществующего индекса — ошибка.
- **`sorted(items)` vs `items.sort()`.** `sorted` возвращает **новый** список, исходный не меняется. `sort` сортирует **на месте** и возвращает `None` — сохранять результат `items = items.sort()` нельзя.
- **Копия списка.** `copy = items` — это два имени одного списка. Чтобы менять независимо, нужен `items.copy()` (в этой работе не требуется, т.к. мы строим новый список через `append`).
- **Исходный список во втором задании сохранён.** Мы не делаем `numbers[i] = abs(...)`, а формируем отдельный список `absolute`.

# Лабораторная работа 7. Функции и автоматические проверки

Индивидуальный вариант — **вариант 8** (числа с модулем не больше порога: `|x| <= threshold`).

## Файлы

| Файл | Назначение |
| --- | --- |
| `functions.py` | Чистые функции без `input()` и `print()` |
| `main.py` | Демонстрация: ввод данных и вызов функций |
| `test_functions.py` | Автоматические проверки через `assert` |

## Запуск

```bash
python test_functions.py   # проверки
python main.py             # демонстрация с вводом
```

## Что делают функции

- **`sum_digits(number)`** — сумма цифр модуля. `abs()` нужен, чтобы отрицательное число приближалось к нулю при `// 10`. Для `0` возвращает `0` без входа в цикл.
- **`average(numbers)`** — среднее списка или `None` при пустом списке. Исходный список не изменяется (используются `sum` и `len`).
- **`normalize_text(text)`** — `" ".join(text.lower().split())`: нижний регистр, без пробелов по краям, один пробел между словами. Исходная строка не меняется (строки неизменяемы).
- **`select_numbers(numbers, threshold)`** (вариант 8) — новый список чисел, для которых `abs(number) <= threshold`. Порядок и повторы сохраняются. Исходный список не изменяется.

## Ключевые идеи

- **Возврат ≠ вывод.** `return` отдаёт значение вызывающему коду; `print()` только показывает его человеку. Все функции здесь возвращают результат и не печатают.
- **Параметр ≠ локальная переменная.** Параметр — имя в определении функции (значение приходит при вызове). Локальная переменная создаётся внутри и после `return` недоступна. `global` не нужен: данные приходят параметрами, результат уходит через `return`.
- **Чистые функции.** `functions.py` не вызывает `input()`/`print()` — такой модуль можно импортировать и проверять через `assert`.
- **Проверки — не замена обработке ввода.** `assert` подходит для учебных тестов, но при оптимизированном запуске (`python -O`) отключается, поэтому пользовательский ввод проверяют условиями и исключениями, а не `assert`.

## Проверки варианта 8

Контрольный набор из задания: `[-5, 0, 2, 5]`, порог `2` → `[0, 2]`.

| Случай | Вход | Результат |
| --- | --- | --- |
| Контрольный | `[-5, 0, 2, 5]`, `2` | `[0, 2]` |
| Пустой список | `[]`, `2` | `[]` |
| Граница включается | `[-2, 2, 3, -3]`, `2` | `[-2, 2]` |
| Рядом с границей | `[3, -3]`, `2` | `[]` |
| Все подходят | `[-1, 0, 1]`, `2` | `[-1, 0, 1]` |
| Все не подходят | `[-10, 10]`, `2` | `[]` |
| Повторы сохраняются | `[2, 2, -2, 3, 2]`, `2` | `[2, 2, -2, 2]` |
| Исходный не изменён | `original = [-5, 0, 2, 5]` | после вызова равен сохранённой копии |

Для варианта 8 при пороге `0` подходит только `0`: `|x| <= 0` ⇔ `x == 0`.

Достаточно заменить в `select_numbers` строку

```python

```

на

if abs(number) < threshold:   # ошибка: граница не включается

— и `assert select_numbers([-2, 2, 3, -3], 2) == [-2, 2]` упадёт с `AssertionError`. Аналогично ловится ошибка `number <= threshold` (без `abs`): для `[-5, 0, 2, 5]` при пороге `2` вернётся `[0, 2, 5]` вместо `[0, 2]`. После проверки функцию возвращают в исправный вид.

## Почему запись удобно представить словарём
Словарь хранит пары «ключ → значение»: у записи о маршруте есть разные по смыслу поля
(`title`, `category`, `amount`). Доступ по имени ключа `record["title"]` читается лучше,
чем `record[0]`, и не зависит от порядка полей. Значения можно менять и добавлять новые
(`record["completed"] = False`) без пересборки структуры, чего нельзя сделать с кортежем.
Кортеж уместен, когда нужна именно неизменяемая пара (например, `(title, hours)`).

## Поведение `.get()`
`dictionary["missing"]` бросает `KeyError`, а `dictionary.get("missing", 0)` возвращает
запасное значение. В подсчётах (`counts.get(word, 0) + 1`) это позволяет обойтись одной
строкой вместо проверки `if word in counts`.

## Зачем сортировать множество перед выводом
У `set` нет гарантированного порядка вывода — он может меняться между запусками.
`sorted(...)` даёт воспроизводимый результат, который удобно сверять в тестах
и показывать пользователю.

## Индивидуальный вариант 8
Предметная область — туристические маршруты, `amount` — целые километры.
Категории: `горный`, `лесной`, `городской` (горный и лесной повторяются).
`totals_by_category` суммирует километры по категориям, `titles_in_category`
возвращает названия в исходном порядке. Входные записи не изменяются.




# Лабораторная работа 9

## Общая проверка
- `row_sums([[1, 2, 3], [4, 5, 6]]) == [6, 15]`
- `column_sums([[1, 2, 3], [4, 5, 6]]) == [5, 7, 9]`
- `row_sums([[7]]) == [7]`, `column_sums([[7]]) == [7]`
- `row_sums([[1], [-1], [0]]) == [1, -1, 0]`, `column_sums([[1], [-1], [0]]) == [0]`
- `row_sums([]) == []`, `column_sums([]) == []`, `transform([]) == []`
- `diagonal_pattern(1) == [[0]]`
- `diagonal_pattern(3) == [[0, 1, 1], [2, 0, 1], [2, 2, 0]]`

## Вариант 8
Отрицательные элементы уменьшаются на 2, остальные сохраняются.
`transform([[-2, 0, 3], [4, -5, 6]]) == [[-4, 0, 3], [4, -7, 6]]`.

## Какую ошибку выявляет таблица 2×3
Если перепутать индексы (`matrix[column][row]`), на матрице 2×3 сразу получится выход за
границы или «перевёрнутые» суммы столбцов. Квадратная 2×2 такую ошибку не покажет —
она маскируется симметрией размеров. Поэтому в тестах используется именно 2×3.

## Почему нельзя повторять одну изменяемую строку
`[[0] * columns] * rows` создаёт `rows` ссылок на **один и тот же** внутренний список.
`matrix[0][0] = 7` изменит первую ячейку во всех строках. Правильный вариант —
`[[0] * columns for _ in range(rows)]`: на каждой итерации создаётся новый список.

## Чем `matrix.copy()` отличается от `[row.copy() for row in matrix]`
`matrix.copy()` копирует только внешний список: строки остаются общими объектами.
`[row.copy() for row in matrix]` создаёт независимые строки — правка `copy[0][0]`
не влияет на исходную матрицу. Это проверяется в `test_transform_does_not_modify_source`.

## Почему `transform` не меняет исходную матрицу
`transform` строит новый внешний список и новые строки через списковые включения:
каждый элемент — новое число, никаких ссылок на старые строки нет. `row_sums`,
`column_sums` и `diagonal_pattern` тоже только читают вход и создают новые структуры.





# Лабораторная работа 10. Текстовые файлы и обработка ошибок

## Формат matrix.txt
Первая строка — два положительных целых числа: `rows columns`.
Далее ровно `rows` строк, в каждой ровно `columns` целых чисел, разделённых пробелами.
После последней строки данных допускается один обычный перевод строки (`\n`).
Пустые строки и лишние строки — ошибка формата. Кодировка — UTF-8.

Контрольный файл:

2 3
1 -2 3
4 0 -6

## Вариант 8
Условие: элементы первой строки. `selected_sum(matrix) = sum(matrix[0])`.
Для `[[1, -2, 3], [4, 0, -6]]` результат `2`.
В матрице 1×1 первая строка совпадает с последней, но элемент учитывается один раз —
это обеспечивает простая `sum(matrix[0])`. Пустая матрица → `0`.

## Отчёт
`report.txt` содержит:
- `Суммы строк: ...`
- `Суммы столбцов: ...`
- `Результат варианта: ...`

Отчёт записывается **только после** успешного чтения и проверки `matrix.txt`.
Исходный файл никогда не открывается в режиме `"w"`.

## Обработка ошибок
- `FileNotFoundError` — файла нет, `main.py` печатает сообщение и завершается.
- `UnicodeError` — файл не читается как UTF-8.
- `OSError` — проблемы доступа (права, каталог и т. п.).
- `ValueError` — неверный формат; `files_lab.read_matrix` бросает его с номером строки.

`read_positive_integer` различает «не целое число» и «должно быть больше нуля».
Ручная проверка последовательности `abc, 0, -2, 3` подтверждает оба сообщения и приём `3`.

## Отличие ошибок формата от ошибок доступа
- Ошибка **формата** (`ValueError`) — данные не соответствуют описанию файла:
  заголовок не из двух чисел, размеры не положительные, ячейка не целое, число
  строк или столбцов не совпадает. Это ошибка входа, её нужно сообщить пользователю.
- Ошибка **доступа** (`FileNotFoundError`, `OSError`, `UnicodeError`) — проблема
  с самим файлом или системой: его нет, нет прав, кодировка не UTF-8. Это отдельный
  класс ситуаций и отдельные сообщения.

## Почему отчёт открывается для записи после проверки входа
`open(REPORT, "w")` сразу стирает прежнее содержимое. Если бы запись начиналась
до проверки `matrix.txt`, при ошибке чтения старый отчёт был бы уже уничтожен.
Поэтому `write_report` вызывается только в `main.py` после успешного `read_matrix`,
и только после него открывается `report.txt`.

## Проверка сохранности старого отчёта (вручную)
1. Запустить `main.py` с корректным `matrix.txt` — создаётся `report.txt`.
2. Испортить `matrix.txt` (например, поставить `1 x` во второй строке).
3. Снова запустить `main.py`. Ожидаем: сообщение «Некорректный формат данных: …»,
   а `report.txt` остался прежним.
Результат: сообщение выведено, `report.txt` не изменился — старый отчёт сохранён.

## Чем tempfile.TemporaryDirectory удобнее ручных файлов
Тесты создают `matrix.txt` во временной папке и удаляют её автоматически.
Это исключает конфликты с реальными файлами и делает тесты независимыми.


# Лабораторная работа 11. JSON и HTTP

## Учебный набор todos.json
Массив объектов; поля `id`, `userId`, `title`, `completed`. Проверка `validate_todos`

## Порядок обработки ошибок в main.py
1. Сначала читаем и проверяем `todos.json`.
2. Только после успешной проверки пишем `leaders.json` и `selected.json`.
3. `json.JSONDecodeError` — подкласс `ValueError`, его обработчик стоит раньше общего.
4. При любой ошибке входных данных прежние `leaders.json`/`selected.json` не трогаются.

## JSON и Python
- `dict` ↔ объект; `list` ↔ массив; `str` ↔ строка; `int`/`float` ↔ число;
  `bool` ↔ `true`/`false`; `None` ↔ `null`.
- `json.dumps(..., ensure_ascii=False)` сохраняет читаемую кириллицу;
  `indent=2` даёт отступы. При работе с файлами — `encoding="utf-8"`.
- Одинарные кавычки и `None` — это Python-литерал, а не JSON. Синтаксически верный
  JSON может не подходить по структуре — это ловит `validate_todos`.

## HTTP-упражнение (fetch_profile.py)
- **Адрес** `https://api.github.com/users/<login>` — ресурс «профиль пользователя»
  в GitHub API. Для репозитория нужен другой ресурс (`/repos/<owner>/<repo>`).
- **GET** — метод чтения ресурса; в этом упражнении данных не отправляем.
- **Таймаут 10 с** ограничивает ожидание, чтобы программа не зависла на медленной сети.
- **Обработчики ошибок**:
  - `HTTPError` — сервер вернул статус (200 — успех; 404 — нет пользователя;
    403/429 — ограничения доступа/частоты).
  - `URLError`, `TimeoutError`, `socket.timeout` — сеть недоступна или превышен таймаут.
  - `ValueError`/`UnicodeError` — неверные данные в ответе или неверная кодировка.
  - `OSError` — проблемы записи `profile.json`.
- **Резерв без сети**: `profile_sample.json` с содержимым
  `{"login": "demo", "id": 1, "name": null}` читается через `json.load`;
  это учебные локальные данные, эквивалентный режим выполнения упражнения.
- Сетевые вызовы не выполняются при импорте: `main()` запускается только из
  `if __name__ == "__main__"`.
