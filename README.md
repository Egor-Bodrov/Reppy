# Лабораторная работа 1. Первые программы на Python

## Состав
- hello.py — первые строки.
- profile.py — карточка студента.
- workload.py — учебная нагрузка.
- debug.py — исправление ошибок.
- swap.py — обмен значениями.

Python 3.13/3.14. В папке lab01:

    python variant.py

## Проверки

### profile.py
- Возраст 17, часы 10.5 → 21; 42.00; 1.50. Факт: совпадает.
- Часы 0 → 0.00; 0.00. Факт: совпадает.
- Возраст 121 → сообщение об ошибке. Факт: совпадает.

### workload.py
- 3×90 и 2×45, доступно 10 ч → 270; 90; 360 мин = 6.00 ч; 4.00 ч; 24.00 ч. Факт: совпадает.
- 0 занятий по обоим → 0; 0; 0.00 ч. Факт: совпадает.
- Доступно 1 ч при нагрузке 6 ч → ошибка. Факт: совпадает.

### debug.py
- А: 5. Б: 18. В: 7.0. Факт: совпадает.

### swap.py
- А-101 и Б-202 → меняются. Одинаковые → остаются. Факт: совпадает.

### variant.py (вариант 8 — «Фотопечать»)
Пример: заказ «Фотопечать», заказчик «Анна Смирнова».
- Малые фотографии: 10 × 15.00 = 150.00
- Большие фотографии: 4 × 45.00 = 180.00
- Товары: 330.00
- Доставка: 20.00
- Итого: 350.00
- Количество: 14
- Внесено: 500.00 → сдача 150.00
Факт: совпадает.

## Пояснения
- **Строка и число:** `input()` возвращает `str`; для вычислений нужно `int()`/`float()`. `"2"+"3"` = «23», `2+3` = 5.
- **Порядок вычислений:** `*` и `/` раньше `+` и `-`; скобки меняют порядок.
- **Временная переменная:** в `swap.py` сохраняет одно значение, чтобы не потерять его при перезаписи.
- **Форматирование денег:** `:.2f` — два знака после точки.

### 3. Предскажите результат (ручной расчёт vs Python)

| Выражение | Ручной прогноз | Результат Python | Объяснение |
|---|---|---|---|
| `2 + 3 * 4` | 14 | 14 | Умножение имеет приоритет над сложением. |
| `(2 + 3) * 4` | 20 | 20 | Скобки меняют порядок вычислений. |
| `17 // 5` | 3 | 3 | Целочисленное деление: 17 = 3×5 + 2. |
| `17 % 5` | 2 | 2 | Остаток от деления. |
| `-7 // 2` | -4 | -4 | В Python `//` округляет вниз к минус бесконечности: -3.5 → -4. |

### 4. Индивидуальный вариант (`variant.py`)
**Задача:** рассчитать количество полных комплектов заданий, остаток и минимальное количество комплектов для размещения всех заданий.

**Формула для округления вверх:**  
Минимальное число единиц = `(total + capacity - 1) // capacity` (при `total > 0`).  
Эта формула позволяет получить округление вверх без использования условных операторов или циклов.

**Примеры проверок:**
| Общее кол-во заданий | В одном комплекте | Полных комплектов | Остаток | Мин. комплектов | Статус |
| --- | --- | --- | --- | --- | --- |
| 0 | 10 | 0 | 0 | 0 | ✅ |
| 20 | 10 | 2 | 0 | 2 | ✅ |
| 21 | 10 | 2 | 1 | 3 | ✅ |

### 4. Индивидуальный вариант (`variant.py`)
Определяет категорию заполненности группы по проценту (0–100).

**Логика условий:**
- Сначала проверяем выход за диапазон: `value < 0` или `value > 100`.
- Затем по порядку проверяем диапазоны: `0–39`, `40–79`, `80–100`. Порядок важен: если поставить проверку на «Почти заполнена» первой, она сработает и для 0, что неверно.

**Примеры проверок:**
| Ввод | Ожидаемый результат     | Фактический результат     | Статус |
|------|-------------------------|---------------------------|--------|
| -1   | Ошибка диапазона        | Ошибка диапазона          | ✅     |
| 0    | Есть места              | Есть места                | ✅     |
| 39   | Есть места              | Есть места                | ✅     |
| 40   | Группа набирается        | Группа набирается          | ✅     |
| 79   | Группа набирается        | Группа набирается          | ✅     |
| 80   | Почти заполнена          | Почти заполнена            | ✅     |
| 100  | Почти заполнена          | Почти заполнена            | ✅     |
| 101  | Ошибка диапазона        | Ошибка диапазона          | ✅     |
